## 从零体验

1. boss 创建会议，设置实际会议时间，选择张三、李四等参会人。
2. 提交短会议文本，或者上传清晰普通话 mp3/wav/m4a。默认上限 50 MB、10 分钟，建议先用 1—3 分钟；文本不超过 12000 字。
3. 录音自动排队转写，再分析并发布有效任务。查看摘要、决策、任务和待补充事项；没有明确负责人的事项不会随意派给某人。
4. 转写有错时展开文本并选择“使用此文本纠错”，编辑后提交新版本。已存在任务不会重复自动派发，管理者可以编辑或选择补建。
5. 员工登录查看自己负责或协作的任务；负责人可开始、完成、重开任务，协作人可填写进展。
6. Boss 查看首页和任务动态，修正人员、期限或内容。仅参与任务而未参会的员工可以看任务摘录，不能借此下载录音或查看会议全文。

失败会显示原因，可重试对应阶段；已保存的转写会复用。转写期间若提交了更新内容，旧转写不会覆盖它。每场会议当前只展示最新录音，不做多文件合并或说话人区分。

## 查询助手

- 免费：页面固定查询按钮；“查找会议：接口清单”为关键词；“语义检索：接口资料由谁整理”为本地向量检索。
- 真实自由问答：例如“会议里关于接口清单作了什么决定？”，模型选择至多一次授权查询，基于实际来源回答。通常一次请求，需会议内容回答时至多两次；没有依据时说明未找到。
- 结果只在当前账号权限内，会议检索只用最新输入版本；点击来源可看原文和版本。相似会议可能一起返回，应按会议标题核对。旧引用仍需通过当前权限检查。
- 助手没有修改任务、任意 SQL 或提权工具，每次问题独立处理。

## 答辩展示：先走一遍这条主线

1. Boss 登录，展示一场已有成功记录的会议，说明原文、纪要、行动事项与任务的关系。已有结果可直接查看，不需要重复模型请求。
2. 切到任务负责人，展示开始、完成和进展记录，再回 Boss 首页查看状态。说明任务状态来自数据库，模型不能凭一句话声称任务已完成。
3. 展示一项缺负责人事项如何补充。如果当前真实结果被归为讨论，可在任务页面手动新建，或用已保存的固定演示场景说明补充流程；固定演示需明确标识。
4. 助手先使用免费按钮或“语义检索：接口资料由谁整理”，打开来源。说明检索先过滤当前账号可看的会议，才计算相关程度。
5. 录音作为补充：查看保存的音频与转写，说明可以“使用此文本纠错”。实际新录音转写完成会自动触发收费分析，演示时按需操作。

## 常见现象，答辩可以这样解释

| 现象 | 原因及操作 |
|---|---|
| 两次分析的任务数量不同 | 模型对行动粒度的判断可能不同。协助安排可能放在协作人中，应看负责人、协作人和内容是否完整，不能只比数量。 |
| 某项没有指定负责人 | 系统不猜人名，待补充后再生成；若模型判成讨论，管理者可看原文后手动建任务。 |
| 转写中有错字 | 使用的是本地小型 CPU 模型，术语和人名可能识别错；纠正转写后再提交。未实现说话人识别和实时录音。 |
| “主要决策”为空 | 模型没有单独提取出明确决策，并不表示分析或任务发布失败；可结合摘要与任务展示，不把空值填成虚假决定。 |
| 分析等待较久或失败 | 外部模型受网络和服务状态影响。格式问题最多尝试修复一次，初次与修复各限时 60 秒；失败后原文保留，可人工重试。 |
| 重新提交文本却没自动增加任务 | 同一场会议已有任务时，为避免重复派发，新版事项由管理者选择补建，原任务人工修改继续保留。 |
| 检索第一次稍慢 | 本地模型首次加载及向量生成需要时间，生成后会缓存。当前只面向少量课设会议。 |

可以概括为：“系统用模型提取会议内容，用程序检查人员、来源和权限，再把有效事项保存为任务；有歧义时交给人补充。它是本地课设原型，已经验证业务闭环，还没有做大规模准确率评估。”

本轮没有增加收费请求，也没有重新分析已有会议。提示词调整只能减少歧义，不能保证每次输出完全一致；如需演示固定结果，可直接展示已有成功记录，并如实说明数据来源。
